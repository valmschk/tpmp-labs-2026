## Разбор ответов на контрольные вопросы
1. Способы создания БД
Тут всё просто: либо ты создаешь файл «руками» через консоль (sqlite3 test.db), либо твоя программа на C сама создает его при первом запуске через sqlite3_open. Третий вариант (:memory:) — это когда база живет только пока работает программа (в оперативной памяти), на диске файла не будет.

2. Список баз (.databases)
В SQLite можно подключить сразу несколько файлов БД к одному сеансу (команда .attach). Поэтому .databases покажет не просто одну базу, а список всех примонтированных файлов и их пути.

3. Экспорт в CSV
CSV — это текстовый формат, где данные разделены запятыми. Чтобы Гит или Excel его поняли, мы:

Включаем заголовки (.headers on).

Меняем режим вывода на запятые (.mode csv).

Перенаправляем вывод из консоли в файл (.output file.csv).

4. Экспорт в .sql и сжатие
Команда .dump превращает твою базу в набор SQL-команд (CREATE, INSERT). Если этот текстовый файл прогнать через архиватор (например, gzip), получится сжатый бекап. Это стандарт индустрии для переноса данных.

5. Вывод по строкам и столбцам
По умолчанию SQLite выводит всё «кашей» через вертикальную черту. Режим .mode column делает красивую таблицу с ровными колонками. Если нужно выбрать конкретные данные, используем классический SELECT.

6. Зачем нужны заголовки (.headers)
Без этой команды ты получишь просто значения: 1 | Valeria | 20. С ней ты увидишь: id | name | age. Это критично для понимания, что за данные перед тобой.

7. Настройки окружения (.show)
Эта команда — «панель управления». Она показывает, какой сейчас разделитель, включены ли заголовки и куда выводится результат (в консоль или в файл).

8. Список таблиц (.tables)
Самая частая команда. Если ты забыла, как точно назвала таблицу (Students или Student), .tables покажет все существующие имена в текущей базе.

9. Выборка из 2-х таблиц (JOIN)
Представь таблицу «Студенты» и таблицу «Группы». Чтобы узнать, в какой группе учится студент, нам нужно их «склеить» по общему полю (например, group_id). Это и делает JOIN.

10. Обновление по условию (UPDATE... WHERE)
Команда UPDATE без WHERE обновит все строки в базе (опасная штука!). Поэтому мы всегда добавляем условие: например, «повысить зарплату только тем, кто работает в отделе IT».

11. Открытие соединения (sqlite3_open)
Это «входная дверь». Пока ты не вызовешь эту функцию, ты не сможешь отправить ни один запрос. Она создает объект-дескриптор (sqlite3 *db), через который идет всё общение.

12. Универсальная функция sqlite3_exec
Это «швейцарский нож». Она берет твою строку с SQL-кодом и исполняет её. Если это запрос SELECT, она использует «callback» — специальную функцию, которая будет вызываться для каждой найденной строчки, чтобы ты могла её напечатать.

13. Закрытие соединения (sqlite3_close)
Если не закрыть базу, файл может остаться «занятым» системой, или данные не успеют сохраниться полностью. Это правило хорошего тона: открыл — поработал — закрыл.

14. Создание таблицы на C
Здесь важно понимать: мы пишем SQL-запрос как обычную строку текста в кавычках и отдаем его функции exec. Программа на C сама по себе не знает, что такое CREATE TABLE, она просто «посредник».

15. Вставка данных на C
Аналогично созданию. Важно следить за кавычками: в языке C строка в двойных кавычках, а внутри SQL-запроса текстовые значения (например, имя 'Valeria') должны быть в одинарных.

16. Транзакции и Autocommit
Это самый важный момент для производительности:

Autocommit: SQLite по умолчанию после каждой вставки открывает и закрывает файл на диске. Если у тебя 1000 строк, он сделает это 1000 раз (очень медленно).

Transaction: Ты говоришь BEGIN. Гит копит все 1000 строк в памяти. Ты говоришь COMMIT. Гит один раз открывает файл и записывает всё махом. Это быстрее в десятки раз.
